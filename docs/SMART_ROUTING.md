# API Key 智能路由

创建或编辑 API Key 时，选择「智能分组」，再选择路由策略。`auto` 会自动使用当前用户全部可用分组，无需手动选择；其他策略可跨厂商选择分组，其中 `sequential` 按用户排列的分组顺序尝试。实际请求仍须满足目标接口和账号的协议、模型及能力要求。单分组模式保留原有行为。

管理员集成接口 `POST /api/v1/integrations/admin/users/:id/api-keys` 和 provision 的 Key 定义省略 `group_id` 时默认使用智能模式，候选为创建时该账号有权绑定的有效分组快照；传入 `group_id` 可创建单分组 Key。分组模型去重、账号/Key 的时间范围用量查询及登录 Token 接口见 [管理员集成接口文档](ADMIN_INTEGRATION_GATEWAY_API.md)。

## 模型列表

智能 Key 的模型列表是所选、有效且仍获授权分组的公开模型 ID 并集。完全相同的 ID 只返回一次，不同公开别名分别保留。例如 A 组包含 `gpt-5`、`claude-sonnet-4`，B 组包含 `gpt-5`、`gemini-2.5-pro`，列表包含三个模型；请求 `gpt-5` 时才在 A、B 两组之间选择线路。

模型白名单与公开映射适用于每个分组；渠道或混合分组的公开别名需要有持久有效的账号支持其映射目标。临时限流、冷却和并发占满不会让模型从列表消失。没有符合条件的模型时返回空列表，不补入默认模型。列表可见不代表当前一定有容量或可用计费额度。

OpenAI 与 Codex 列表按公开 ID 合并；Codex 中同名模型的能力描述取保守交集，避免宣称只有部分线路支持的能力。Gemini 原生接口只展示其协议可用的模型，当前使用本地模型描述。

## 五种策略

| 策略 | 新请求的选择规则 |
| --- | --- |
| 自动选择 `auto` | 使用创建或编辑时账号当前全部可用分组的快照，沿用已有账号调度规则，包括优先级、负载及管理员配置的调度器。 |
| 按顺序 `sequential` | 必须指定至少一个分组，严格按 `smart_group_ids` 的顺序依次尝试；每个分组内沿用账号调度器。 |
| 价格优先 `price` | 优先有空闲容量的线路，再按相同预估工作量比较用户费用。使用实际计费计算器及分组规则；零价是已知免费价格，未知价格排在已知价格后。最终按实际用量结算，预估不承诺最低账单。 |
| 速度优先 `speed` | 优先有空闲容量的线路，在有样本的账号之间比较对应上游模型的首字延迟；无样本账号保留常规调度次序。 |
| 随机选择 `random` | 在符合条件且有容量的分组间等概率选择，组内沿用原调度器。账号多的分组不会因此获得更高随机权重。 |

速度样本按「账号 + 实际上游模型」记录，采用移动平均，一小时无更新后失效。目前样本保存在单个服务进程中，重启后重新积累，多实例之间不共享样本。

## 会话与续传

有会话标识的请求优先复用原分组和账号，先前会话选择优先于新的价格、速度或随机偏好。分组绑定通过 Redis 原子操作维护，避免并发请求分别绑定不同分组。普通请求在原分组不可用时可按既有调度规则重新选择。

工具结果续传和 `previous_response_id` 必须使用原分组及原账号。无法确认归属、归属冲突、授权被撤销或原线路不可用时返回错误，不能迁移到另一条上游会话。客户端应保持会话标识稳定；需要改用新线路时，应开启新的会话。

## 权限与计费

创建和编辑 Key 时校验分组授权，每次鉴权重新加载可用分组并校验授权。分组删除、停用或授权撤销后不再参与模型列表与调度。实际请求在选定分组后执行该分组的白名单、协议、订阅、限流及并发规则；Key 自身的额度、过期时间和 IP 限制仍适用。

费用、订阅额度和用量归属按请求实际选中的分组记录。共享账号同时属于多个分组时，也不能按账号成员顺序猜测计费分组。异步图片任务将并发预留转交后台任务，直到使用结束或失败后释放。

同时选择订阅组和余额组时，订阅组额度不足可能使用所选余额组并扣除余额。需要只使用订阅额度的 Key，应只选择相应订阅分组。固定归属的工具续传不参与这类跨组回退。

`GET /v1/sub2api/billing` 对智能 Key 返回 `schema_version: 2`、路由策略及各分组的计费信息；客户端应分别读取各分组，不能假定整个 Key 只有一个倍率。该接口展示分组计费配置，并非完整的逐模型报价接口。
