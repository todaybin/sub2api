# 积分扣费

## 开启方式

1. 在管理员「分组管理」的添加或编辑表单中开启「允许积分扣费」。不需要新增分组类型。
2. 在同一表单设置本分组「1 美元对应多少积分」，例如 100。系统金额单位沿用 USD，各分组可使用不同的比例，不使用全局比例。开启时比例必填，范围为 0.00000001–999999999999，保留 8 位小数。
3. 在管理员用户列表点击积分余额，可以增加、扣除或设置积分，也可以查看流水。管理员也可以生成「积分」兑换码供用户充值。

升级启动时按现有迁移流程执行 `243_points_billing.sql` 和 `245_group_points_rate.sql`。已有账号积分默认为 0，已有分组开关默认为关闭；升级本身不会把金额余额转换成积分。245 将合法的旧全局比例一次性回填到已开启积分的分组；没有合法旧值时比例保持 0，需要管理员在分组中配置后才能使用积分。旧全局设置请求中的 `points_per_usd` 会被忽略。

## 付款顺序

有效订阅优先使用订阅，并继续执行订阅限额。没有有效订阅时，标准分组关闭积分就使用原有金额余额；开启积分就使用积分，可用积分不大于 0 时拒绝调用，即使金额余额充足也不会回退扣金额。订阅类型分组关闭积分且没有有效订阅时，仍按原规则拒绝调用。

积分费用 = 原有规则算出的最终扣费金额 × 请求准入时的本分组兑换比例。例如实际费用 0.02 USD、比例 100，则扣 2 积分；每轮按实际用量扣费，不设固定每轮积分。模型价格、分组倍率、用户倍率和高峰倍率仍按现有逻辑计算，不另设模型积分价格。积分按 8 位小数存储。请求开始后修改分组比例，不影响该请求的预留和结算快照。

最后一笔请求允许积分透支。例如余额 30 积分、1 USD = 100 积分，实际费用为 1 USD，则结算后为 -70 积分。这笔请求不会拆成积分和金额两次付款。再充值 100 积分后余额为 30；金额充值不抵扣积分欠款。

## 用量与限制

首版覆盖文本请求、流式文本及 OpenAI Responses WebSocket 的每轮响应。显式图片、视频和音频请求继续使用金额计费。简易模式不扣积分。

并发请求会占用积分，后续积分请求按「积分余额减在途占用」判断准入。API Key 美元配额、速率窗口、账号配额和用户平台美元限额继续按原有金额计算。积分流水记录扣除积分、对应美元费用及当次兑换比例；用量记录支持积分过滤和导出。

用户仪表盘分别展示积分余额、累计积分消耗和金额余额消费。现有用量图表里的美元费用属于按价格规则计算的计价金额，包含积分支付和订阅用量。金额消费汇总只覆盖保留的用量记录；积分流水独立于用量日志清理。

## 结算与恢复

积分结算使用持久化预留、请求幂等键和数据库事务，积分扣除与 API Key、上游账号的美元配额更新一同提交，重复结算不会重复扣费。用户平台配额沿用原有缓存累加和后台持久化方式。已保存的待结算命令由后台恢复任务重试；没有提交计费任务的预留会释放，异常中断的活动预留有租约过期处理。

持久化恢复从计费命令写入数据库开始。进程在取得上游结果后、保存计费命令前崩溃的情况，仍需要人工核对上游用量，不能据此宣称所有崩溃场景都保证记账。

## 接口

- `POST /api/v1/admin/users/:id/points`：`points`、`operation`（`add` / `subtract` / `set`）、`notes`。调用方应提供稳定的 `Idempotency-Key` 以安全重试。
- `GET /api/v1/admin/users/:id/points-history`：管理员积分流水。
- `POST /api/v1/integrations/admin/users/:id/points`：第三方签名网关积分充值，使用 `{"points":1000,"operation":"add","notes":"订单号"}`；必须提供完整联合认证及稳定 `Idempotency-Key`。直接增加积分，不转换金额，响应包含 `points_balance`、`points_reserved`。
- `GET /api/v1/integrations/admin/users/:id/points-history`：第三方签名网关查询积分流水。请求与响应示例见 [集成网关 API 文档](../docs/ADMIN_INTEGRATION_GATEWAY_API.md#531-增加积分与查询积分流水)。
- `GET /api/v1/user/points-history`：当前用户积分流水。
- `GET /api/v1/user/points-summary`：当前用户累计积分消耗、积分对应美元费用和保留记录中的金额扣费。

流水使用现有 `page`、`page_size` 分页。已有请求占用积分时，管理员只能增加积分，设置或扣除需要等待请求结算。
